# PROJECT RiNG — v53

MyGO!!!!! 비공식 팬 창작 카페 경영 게임. v53은 저장 무결성·이미지 로딩·조작 동선·검증 체계를 개선하는 패치입니다. [플레이 사이트](https://project-ring-mygo-cafe.tsiba5021.chatgpt.site/)

## 실행과 개발

Node.js 24를 기준으로 검사합니다. Node.js 22 이상에서 사용할 수 있습니다.

```sh
npm ci
npm test
npm run build
npm run verify-build
npm start
```

http://127.0.0.1:8765/ 를 엽니다. `app/`은 편집하는 원본, `dist/`는 게시하는 빌드입니다. 이미지 원본과 WebP 파생본을 함께 보존합니다. `npm run assets`는 고정 버전 sharp로 파생본을 재생성하며 일반 빌드에는 재변환이 필요하지 않습니다.

## v53 변경

- 자동·슬롯·파일 저장에 공통 판독기·이행·불변식 검사 적용. 손상 원본 보존, 이전 정상 저장 복구, 저장 중/실패 표시.
- 첫 VN/첫 영업만 준비하는 이미지 묶음, 6초 요청 제한, 취소·실패 재시도, 독립 표시 노드와 10장/24MiB 참조 캐시 상한.
- 기본 크기 PNG 42장 57.50MB → WebP 파생본 4.74MB. 첫 플레이 이미지 묶음 1.94MB. 실제 GPU 메모리나 실기기 속도 측정치가 아닙니다.
- 음악 버튼을 헤더로 이동하고 현재 업무 모드 바로 열기, 발주 화면에서 개점하기 추가. 미결제 발주를 자동 결제하거나 버리지 않습니다.
- 문장 정규식 대신 명시적 표정·생각·beat ID, 원문 문자열 대신 서비스 대사 ID. 기존 대본의 본문·조건·보상 유지.
- 동일 입력에서 같은 파일이 나오는 빌드. 해시 이름 JS/CSS, 버전 이미지 URL, CSP, 파일 무결성 manifest.

## 검사와 배포

`npm test`는 과거 백업 파일 해시와 분리된 문법·회귀 검사 94개입니다. 현 엔진 10시드×42일, 현금 등식·저장·중간 복원 및 조건을 갖춘 마감 장면 100종의 스케줄을 포함합니다. 한 회차에서 110개를 모두 감상했다는 뜻은 아닙니다.

GitHub Actions는 push/PR마다 검사·빌드·무결성과 Chromium/Firefox/WebKit의 핵심 흐름을 실행합니다. 결과는 Actions에서 확인하세요. 실제 휴대기기, 화면 낭독기, 30분 메모리·INP 측정 및 청취 검수는 별도입니다.

`npm run verify-build`는 새 빌드를 검사합니다. `npm run verify-snapshot`은 보존된 v53 백업을 검사합니다. 소스를 고치면 과거 백업 검사는 다를 수 있으며, 이 때문에 개발 테스트를 먼저 막지 않습니다.

과거 복원 지점 `v47`, `v52`는 유지합니다. 버전별 복원은 `git switch --detach v52`처럼 태그를 선택하세요. 게시에는 `dist/`만 사용하며 로컬 개발 서버는 운영용 서버가 아닙니다.

## 저장·권리

개인 플레이 진행은 브라우저 localStorage에 있습니다. GitHub나 진단 파일에 포함하지 않으며 게임 설정의 백업 기능으로 따로 보관하세요. 진단 파일은 사용자가 눌러 내려받으며 원격 수집하지 않습니다.

이 저장소가 공개되어 있다는 사실이 원작 IP·제공 음악·그림의 재사용 또는 정식 출시 권한을 뜻하지 않습니다. [권리 상태](docs/RIGHTS-STATUS.md)와 [음악 크레딧](dist/assets/MUSIC-CREDITS.txt)을 확인하세요. 코드 라이선스도 임의로 새로 부여하지 않았습니다.
