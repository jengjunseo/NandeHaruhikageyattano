# PROJECT RiNG — v54

MyGO!!!!! 비공식 팬 창작 카페 경영 게임입니다. v54에서는 아침 이야기에서 고른 운영 방식이 영업, 마감, 다음 방문까지 이어집니다. [플레이 사이트](https://project-ring-mygo-cafe.tsiba5021.chatgpt.site/)

## 실행과 개발

Node.js 24를 기준으로 검사합니다. Node.js 22 이상에서 사용할 수 있습니다.

```sh
npm ci
npm test
npm run build
npm run verify-build
npm start
```

http://127.0.0.1:8765/ 를 엽니다. `app/`은 편집하는 원본, `dist/`는 게시하는 빌드입니다. 이미지 원본과 WebP 파생본을 함께 보존합니다. `npm run assets`는 고정 버전 sharp로 파생본을 재생성하며 일반 빌드에는 재변환이 필요하지 않습니다.

## v54 변경

- 토모리의 창가 예약표와 아논의 추천 칠판은 해당 아침 장면을 읽은 날에 준비할 수 있어요.
- 공연 세트는 기본 메뉴만 판매, 재료 공유, 최대 2인분 확보 중에서 선택할 수 있어요. 확보한 재료는 세트에 우선 사용하고 남으면 일반 재고로 돌아옵니다.
- 단골이 지난번에 받은 메뉴를 기억하고, 타키가 주문을 건네면 메뉴와 금액 및 손님의 반응을 보여 줍니다.
- 영수증에 표시된 주문 원인을 다음 날 메뉴·발주·업무 설정에 연결합니다. 준비 서랍에서는 발주와 개점 버튼을 하단에 표시합니다.
- v53 저장은 열 때 이전합니다. 확보량·예약표·추천 칠판은 v54의 해당 선택에서 시작합니다.

## v53 기록

[검수 반영과 남은 항목](docs/V53-CHANGES.md) · [게시/CI 기록](docs/V53-RELEASE.json)

- 자동·슬롯·파일 저장에 공통 판독기·이행·불변식 검사 적용. 손상 원본 보존, 이전 정상 저장 복구, 저장 중/실패 표시.
- 첫 VN/첫 영업만 준비하는 이미지 묶음, 6초 요청 제한, 취소·실패 재시도, 독립 표시 노드와 10장/24MiB 참조 캐시 상한.
- 기본 크기 PNG 42장 57.50MB → WebP 파생본 4.74MB. 첫 플레이 이미지 묶음 1.94MB. 실제 GPU 메모리나 실기기 속도 측정치가 아닙니다.
- 음악 버튼을 헤더로 이동하고 현재 업무 모드 바로 열기, 발주 화면에서 개점하기 추가. 미결제 발주를 자동 결제하거나 버리지 않습니다.
- 문장 정규식 대신 명시적 표정·생각·beat ID, 원문 문자열 대신 서비스 대사 ID. 기존 대본의 본문·조건·보상 유지.
- 동일 입력에서 같은 파일이 나오는 빌드. 해시 이름 JS/CSS, 버전 이미지 URL, CSP, 파일 무결성 manifest.

## 검사와 배포

`npm test`는 문법·회귀 검사 95개를 실행합니다. 5일짜리 기본·실험 영업, 같은 시드의 공연 재고 비교, v53 저장 5종 이전, 그리고 현 엔진의 10시드×42일 회귀를 포함합니다.

GitHub Actions는 push/PR마다 검사·빌드·무결성과 Chromium/Firefox/WebKit의 핵심 흐름을 실행합니다. 결과는 Actions에서 확인하세요. 실제 휴대기기, 화면 낭독기, 30분 메모리·INP 측정 및 청취 검수는 별도입니다.

`npm run verify-build`는 새 빌드를 검사합니다. `npm run verify-snapshot`은 현재 체크아웃의 보존 백업을 검사합니다.

버전별 복원은 `git switch --detach v53`처럼 태그를 선택하세요. 게시에는 `dist/`를 사용합니다.
