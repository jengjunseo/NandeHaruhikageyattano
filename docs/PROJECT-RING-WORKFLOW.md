# PROJECT RiNG 개발·검증 흐름

작은 수정마다 전체 배포하지 않고, 서로 관련된 개선을 한 작업 단위로 묶는다. 중간에는 변경 분야의 빠른 검사를 사용하고, 사이트에 반영할 때만 전체 회귀와 배포를 한 번 실행한다.

- 대사·이야기 작업 중: `node work/ring-pipeline.cjs --scope story`
- 영업·저장·경영 작업 중: `node work/ring-pipeline.cjs --scope game`
- 이미지·연출 작업 중: `node work/ring-pipeline.cjs --scope visual`
- 배포 직전: `node work/ring-pipeline.cjs --scope all --stage`

스크립트는 관련 검사를 최대 4개씩 병렬 실행한다. 배포 직전 단계는 전체 검사에 실패하면 사이트 파일을 복사하지 않는다. 성공하면 변경된 게임 파일만 기존 사이트 작업본으로 복사한다. 문서와 비밀 값은 사이트에 복사하지 않는다. 이미 배포된 소스와 실질적 차이가 없다면 저장·배포를 건너뛴다. 사이트 게시에는 기존 Sites 공식 워크플로를 사용하며 임시 인증값은 메모리와 표준 입력으로만 전달한다.

브라우저 검수는 매 대사 수정 때마다 반복하지 않는다. 작업 묶음에서 실제로 달라진 사용자 흐름을 한 번 확인하고, 게임 구조·입력·반응형·시청각이 달라졌을 때 해당 화면과 경로를 직접 점검한다. 여러 항목이 같은 흐름을 건드리면 한 번의 플레이에서 함께 확인한다. 자동 검사는 원작의 말투와 게임의 재미, 실제 태블릿 터치나 소리 감상을 증명하지 않으므로 최종 검수에서는 따로 확인한다.
